## The Problem

The university heating plant was built in 1969 and heats 17 campus buildings through underground steam pipes. It runs on three large natural gas boilers with about 3,400 total boiler horsepower.

Steam boilers take hours to warm up, and large buildings take time to heat up or cool down:

* If operators underestimate how much heat is needed, buildings get cold and the plant has to scramble to catch up.
* If they overestimate, the boilers burn extra gas and vent expensive steam into the air.

For years, operators had to manually guess boiler settings based on past experience and outdoor temp sensors. The goal of this project was to give operators an accurate next-day hourly forecast so they can adjust boiler output before big weather changes hit.

---

## The Data Pipeline

The system pulls live data from over 400 sensors across the plant and connected buildings:

* **Messy sensor data**: Industrial sensors frequently lose power or drop off the network. I built an ingestion pipeline in Python using Kafka and Redis caching. If a sensor drops offline, the system uses the last good reading and retries in the background. This kept the pipeline at 98% uptime and cut data delays by up to 90 seconds.
* **Reading gas meters with OCR**: Several gas meters were older mechanical dials with no digital output. I set up cameras and wrote an OpenCV and Tesseract OCR script to read the numbers automatically off the dials.
* **Tracking building occupancy**: A building packed with people needs less heat than an empty building. I used OpenCV to estimate general occupancy trends so the model knows when buildings are actually being used.

---

## Forecasting Models

Steam demand depends heavily on the weather, but also on building construction and recent usage:

* **Practical features**: I added features for building thermal retention (how long brick and concrete hold heat), wind chill, occupancy schedules, and boiler history.
* **PyTorch models**: I tested four sequential architectures: LSTM, Bidirectional LSTM, GRU, and ConvLSTM.
* **Results**: The best model brought forecast accuracy from an 81% baseline to 94%, giving operators reliable next-day numbers to plan boiler schedules.

---

## Monitoring & Safety

Because this is a real heating plant, the AI never controls physical valves directly:

* **Live dashboard**: I built a real-time web dashboard showing live steam demand, upcoming forecasts, and sensor health warnings.
* **Alerts and reports**: I used LangGraph and MCP to generate automated daily reports and alerts. The system suggests boiler adjustments, but an operator must review and approve every change.
* **Retraining**: I set up GitHub Actions to run automated data tests and retrain models as the weather shifts between seasons.
